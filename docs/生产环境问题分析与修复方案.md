## 问题总结

### 1. 开仓频率极低
- **数据**: 6个候选币种中只有1个开仓（SOLUSDT），开仓率仅16.7%
- **原因**: 大量交易被方向冲突阻断

- **根本原因**: 方向裁决逻辑存在系统性偏差

## 核心问题分析

### 问题1: 方向冲突导致开仓率过低

#### 现象
```
BTC/ETH: plan_side=UNKNOWN (OF_STALE阻断)
BNB/XRP/DOGE: plan_side=NEUTRAL (DIR_CONFLICT阻断)
- HTF结构偏空 (plan_side=SHORT)
- 5m触发器为多头 (EDGE_BULL, quality=0.81-0.91)
- 结果: 方向冲突，禁止开仓
```

#### 根本原因
**trigger_context与direction_arbitration的方向判断脱节**

1. **trigger_context (5m EDGE触发器)**
   - EDGE_BULL: 检测到价格触碰支撑位（锚点下沿）
   - 逻辑: 触碰支撑 → 可能反弹 → 多头信号
   - 质量: 0.81-0.91 (高质量)

2. **direction_arbitration (HTF结构方向)**
   - plan_side=SHORT
   - 基于: 15m/30m/1h下降趋势 + 订单流偏空
   - struct_dir=-0.1 (轻度看跌)

3. **AI决策层**
   - 检测到方向冲突: trig_dir=LONG vs plan_side=SHORT
   - 判定: 不满足翻转白名单（4h RSI=44.3，非极值）
   - 结果: block_entry=true，禁止开仓

#### 问题本质
**EDGE触发器的方向语义错误**

- EDGE_BULL触碰支撑位 ≠ 立即做多
- 在下降趋势中，触碰支撑位可能是：
  1. 短暂反弹后继续下跌（假突破）
  2. 支撑位被击穿（支撑失效）
  3. 真正的反转（概率较低）

**当前逻辑错误地将"触碰支撑"解读为"做多信号"，导致与HTF空头趋势冲突**

```
HTF锚点:

- Anchor2: 4h supply 85.18-82.39 (上方阻力)
- 当前价: 82.79 (位于4h供应区下沿)
```

#### 亏损原因分析

1. **信号强度不足**
   - struct_dir=-0.1, of_dir=-0.13 (都是轻度看跌)
   - 这种弱信号在震荡市中容易被噪音干扰

2. **入场位置不佳**
   - 价格82.79已经在供应区下沿
   - EDGE_BEAR触发说明价格触碰了阻力位上沿(85.18)
   - 但入场价82.8说明价格已经回落了2.4点
   - **问题**: 错过了最佳做空点位（阻力位附近）

3. **风险回报比不足**
   - R_clean=0.59 < 1.0 (风险大于回报)
   - 止损距离2.8点，止盈距离1.7点
   - 在弱趋势中，这种RR比很难盈利

4. **市场环境不利**
   - trend_alignment="divergent_mixed" (现货期货分歧)
   - 4h RSI=44.3 (中性区域，非超买)
   - 15m/30m/1h RSI=30-40 (接近超卖)
   - **问题**: 在接近超卖区域做空，容易遇到反弹

## 修复方案

### 方案A: 修复EDGE触发器的方向语义（推荐）

#### 核心思路
**EDGE触发器不应该直接给出方向，而是标记"结构测试事件"**

#### 实现步骤

1. **重新定义EDGE触发器语义**
```go
// 当前错误逻辑
EDGE_BULL: 触碰支撑 → 做多信号
EDGE_BEAR: 触碰阻力 → 做空信号

// 修正后逻辑
EDGE_BULL: 触碰支撑 → 支撑测试事件（方向待定）
EDGE_BEAR: 触碰阻力 → 阻力测试事件（方向待定）
```

2. **方向由HTF结构决定**
```go
// 在下降趋势中
if struct_dir < -0.3 && trigger == EDGE_BEAR {
    // 触碰阻力 + 下降趋势 → 做空（顺势）
    final_dir = SHORT
} else if struct_dir < -0.3 && trigger == EDGE_BULL {
    // 触碰支撑 + 下降趋势 → 观望（可能跌破支撑）
    final_dir = NEUTRAL
}

// 在上升趋势中
if struct_dir > 0.3 && trigger == EDGE_BULL {
    // 触碰支撑 + 上升趋势 → 做多（顺势）
    final_dir = LONG
} else if struct_dir > 0.3 && trigger == EDGE_BEAR {
    // 触碰阻力 + 上升趋势 → 观望（可能突破阻力）
    final_dir = NEUTRAL
}
```

3. **修改trigger_context输出**
```go
// 当前输出
{
    "trigger_primary": "EDGE_BULL",  // 暗示做多
    "trigger_flags": ["EDGE_BULL"]
}

// 修改为
{
    "trigger_primary": "EDGE_SUPPORT_TEST",  // 中性描述
    "trigger_flags": ["EDGE_SUPPORT_TEST"],
    "trigger_level_type": "support",  // 标记是支撑还是阻力
    "trigger_direction_hint": "NEUTRAL"  // 不预设方向
}
```

#### 代码修改位置
- `triggers/edge.go`: 修改EDGE触发器的命名和语义
- `market/data.go:4524-4546`: 修改trigger_context的输出格式
- AI提示词模板: 更新对EDGE触发器的解读逻辑

### 方案B: 优化方向裁决权重（辅助方案）

#### 问题
当前权重配置导致弱信号也能通过：
```go
// internal/direction/compute.go:163-173
ofDir := clamp(
    0.15*macroSign +    // 宏观趋势: 15%
    0.15*intentSign +   // 蜡烛意图: 15%
    0.30*cvdSign +      // CVD: 30%
    0.10*oiSign +       // OI: 10%
    0.20*obSign +       // 订单簿: 20%
    0.10*wallSign,      // 墙: 10%
    -1, 1,
)
```

#### 优化建议

1. **提高信号强度阈值**
```go
// 当前配置
cfg.ThetaNeutral = 0.15  // delta阈值
cfg.MinConf = 0.50       // 最小置信度

// 建议修改
cfg.ThetaNeutral = 0.25  // 提高到0.25，过滤弱信号
cfg.MinConf = 0.60       // 提高到0.60，要求更高置信度
```

2. **增加趋势强度过滤**
```go
// 在ComputeDirectionArbitration中增加
if abs(structDir) < 0.3 && abs(ofDir) < 0.3 {
    // 结构和订单流都是弱信号，强制NEUTRAL
    side = SideNeutral
    flags = append(flags, "WEAK_SIGNAL_FILTERED")
}
```

### 方案C: 优化RR比和入场时机

#### 问题
- R_clean=0.59 < 1.0 (风险大于回报)
- 入场时机滞后（价格已经回落）

#### 优化建议

1. **提高最小RR比要求**
```go
// AI提示词中的rr_min配置
rr_min: 0.45  // 当前值

// 建议修改
rr_min: 0.80  // 提高到0.8，确保风险回报合理
```

2. **优化入场时机判断**
```go
// 在trigger_context中增加价格偏离度检测
trigger_price_deviation := abs(current_price - trigger_level) / atr5m

if trigger_price_deviation > 1.5 {
    // 价格已经偏离触发点位超过1.5个ATR
    // 标记为"入场时机已过"
    flags = append(flags, "ENTRY_TIMING_MISSED")
    // 降低触发器质量评分
    trigger_quality *= 0.5
}
```

3. **增加趋势强度要求**
```go
// 只在强趋势中交易
if abs(struct_dir) < 0.4 {
    // 趋势不够强，提高RR比要求
    rr_min = 1.2
}
```
