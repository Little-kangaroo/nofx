# 方向裁决系统优化报告

**日期**: 2026-01-25
**优化模块**: internal/direction
**优化目标**: 提高信号质量，减少亏损交易，保留盈利机会

---

## 一、优化背景

### 1.1 问题发现

通过对历史交易记录的回测分析，发现两笔亏损交易：
- **亏损案例1** (records_new/亏损9.6%.txt): SHORT交易，亏损9.6%
- **亏损案例2** (records_new/亏损13.6%.txt): SHORT交易，亏损13.6%

### 1.2 问题分析

两笔亏损交易的共同特征：
1. **多时间框架信号矛盾**：15m与1h时间框架出现相反信号
2. **横盘通道假突破**：flat通道的breakup/breakdown信号可靠性低
3. **1h矛盾信号未被识别**：系统判断方向与1h通道位置存在矛盾

---

## 二、优化方案

### 2.1 初始优化尝试（已回滚）

**方案内容**：
- 降低 flat 通道突破信号强度（breakup/breakdown 从 ±1.0 降至 ±0.5）
- 调整订单流与结构权重（订单流 50-65%，结构 35-50%）

**测试结果**：
- ✅ 成功拦截两笔亏损交易
- ❌ 误拦截盈利交易 data17（ETHUSDT LONG，盈利交易）

**问题**：过度保守，导致信号相互抵消，错失盈利机会

### 2.2 最终优化方案

**核心思路**：分离信号计算与风险拦截
- 保持信号强度不变（不降级 flat 通道突破）
- 通过 block_entry 机制精准拦截危险交易
- 恢复订单流主导地位（70-85%权重）

## 三、具体修改

### 3.1 回滚 channelSign 降级逻辑

**文件**: `structdir.go`

**修改前**：
```go
case "breakup":
    if quality < 0.50 {
        return 0.30
    }
    if dir == "flat" || dir == "sideways" {
        return 0.50  // 降级
    }
    return 1.0
```

**修改后**：
```go
case "breakup":
    if quality < 0.50 {
        return 0.30
    }
    return 1.0  // 不降级
```

### 3.2 恢复订单流权重

**文件**: `config.go`

**修改前**：
```go
WOFMin: 0.50,  // 订单流权重最小值
WOFMax: 0.65,  // 订单流权重最大值
```

**修改后**：
```go
WOFMin: 0.70,  // 订单流权重最小值
WOFMax: 0.85,  // 订单流权重最大值
```

### 3.3 优化 1h 矛盾信号检查

**文件**: `compute.go` (lines 267-286)

**核心改进**：区分强矛盾与弱矛盾

**修改后逻辑**：
```go
// 判断做空，但1h向上突破（排除flat通道的弱信号）
if side == SideShort && pos1h == "breakup" && dir1h != "flat" && dir1h != "sideways" {
    blockEntry = true
    blockReason = "1H_BREAKUP_CONFLICT"
}

// 判断做多，但1h向下突破（排除flat通道的弱信号）
if side == SideLong && pos1h == "breakdown" && dir1h != "flat" && dir1h != "sideways" {
    blockEntry = true
    blockReason = "1H_BREAKDOWN_CONFLICT"
}
```

**关键改进**：
- ✅ 横盘通道（flat/sideways）突破 → 不拦截（弱信号）
- ✅ 趋势通道（up/down）矛盾突破 → 拦截（强信号）

## 五、优化效果总结

### 5.1 核心成果

1. **成功拦截亏损交易**：两笔历史亏损交易均被正确拦截
2. **保留盈利机会**：盈利交易 data17 正确放行
3. **精准风险控制**：通过区分强弱矛盾信号，实现精准拦截

### 5.2 关键改进点

| 改进项 | 优化前 | 优化后 | 效果 |
|-------|-------|-------|------|
| 信号强度 | 降级 flat 突破 | 保持原强度 | 避免信号抵消 |
| 订单流权重 | 50-65% | 70-85% | 恢复主导地位 |
| 1h矛盾检查 | 无条件拦截 | 区分强弱信号 | 精准拦截 |

### 5.3 拦截机制

**保留的拦截机制**：
1. **多时间框架 flat+breakdown 聚集检查**：2个及以上时间框架出现 flat+breakdown
2. **1h 强矛盾信号检查**：1h 趋势通道（非 flat）出现矛盾突破

**拦截逻辑**：
- SHORT 判断 + 1h 非flat通道 breakup → 拦截
- LONG 判断 + 1h 非flat通道 breakdown → 拦截
